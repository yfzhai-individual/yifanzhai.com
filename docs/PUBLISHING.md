# Publishing

The repository is the CMS. Articles are statically generated by Astro and published through the Git workflow:

**Draft → local preview → validation → pull request → Cloudflare preview → visual review → merge → production verification**

The repository contains no Cloudflare configuration or deployment workflow. Its documented deployment assumption is an externally configured Cloudflare Pages project connected to GitHub, with `main` as the production branch, `npm run build` as the build command, `dist` as the output directory, and Node.js 22. Under that setup, pull requests receive preview deployments and merges to `main` trigger production deployment. Confirm those settings in Cloudflare if behavior differs.

## Process

1. Run `npm run new:post -- <slug>` to create an evergreen `.mdx` draft under `src/content/writing/` from `_template.mdx`.
2. Write and review locally with `npm run dev:drafts`. The draft appears on `/writing/` with a `Draft` indicator and has its own article route.
3. When the article is ready for a publishing review, set `draft: false` and run `npm run validate`, followed by `npm run preview` for the production output.
4. Commit the focused changes, push a branch, and open a pull request. Do not include unrelated code or design changes.
5. Wait for the Cloudflare Pages preview if the external integration is enabled. Cloudflare runs the production build, so articles left as `draft: true` are excluded. Set `draft: false` in the publishing PR only when the article is ready for that preview and for publication on merge.
6. Review the preview visually and technically. Fix issues on the branch and allow the preview to rebuild.
7. Merge only after approval. Merging a `draft: false` article to `main` is the publishing action; agents must not merge or publish unless explicitly asked.
8. After deployment, open the production article, `/writing/`, and `/rss.xml`. Confirm the canonical URL works and the article appears where expected.

## Publishing checklist

- [ ] Frontmatter matches `src/content.config.ts`; title, description, publication date, and tags are final.
- [ ] `draft: false` is intentional and appears in the reviewed pull-request diff.
- [ ] Internal and external links open the intended public destinations.
- [ ] Images load, are appropriately sized, and have useful alt text (or empty alt text when decorative).
- [ ] Code fences specify the correct language and code is readable without accidental secrets or private data.
- [ ] Article and table of contents render correctly on desktop.
- [ ] Article, tables, images, and code overflow behave correctly on a narrow mobile viewport.
- [ ] Text, links, diagrams, and syntax highlighting are legible in dark mode.
- [ ] `npm run validate` succeeds locally and the Cloudflare preview build succeeds.
- [ ] The production article, writing index, and RSS feed are verified after merge.

## Validation coverage

`npm run validate` currently runs the existing production build, which performs `astro check` and `astro build`. This validates Astro files, TypeScript, content schema/frontmatter, MDX compilation, and static generation without adding dependencies.

Draft preview is guarded by both Astro's development environment and the explicitly selected `drafts` mode. Production builds and Cloudflare previews cannot enable it through the mode alone. RSS and the homepage always apply their own published-only filters.

Formatting enforcement, prose linting, and comprehensive broken-link checking are not configured. Add them only when their maintenance value justifies the dependency and configuration cost. Until then, review formatting and links manually in the production and Cloudflare previews.
